## Example: Medicare Workflow (How It Works)

```
START
  ↓
PREREQUISITE_CHECK (first_name, last_name, license_number)
  ├─[met]─→ GENERATE_TASK (Submit Medicare Application)
  └─[not_met]─→ [Generates "Complete Info" task, waits]
       ↓
WAIT_FOR_DATE (application_submission_date)
  ↓
AUTO_COMPLETE_TASK (Submit Medicare Application)
  ↓
  ├─→ GENERATE_TASK (Attach Evidence)
  └─→ GENERATE_TASK_WITH_DUE_DATE (Track Approval, due in 30 days)
       ↓
WAIT_FOR_DATE (application_approved_date)
  ↓
  ├─→ GENERATE_TASK (Enter Loading Date)
  └─→ UPDATE_PROVIDER_FIELD (credentialing_loaded_date = today)
       ↓
WAIT_FOR_DATE (provider_loaded_date)
  ↓
COMPLETE
```

## Technical Notes

### React Flow Integration
- Store complete React Flow state in `workflow_data` JSONB field
- Nodes have IDs like "node_1", "node_2"
- Edges connect via source/target IDs
- Handles specify which output connects (default, met/not_met, true/false)

### Execution Model
- Workflows start on payer assignment
- Execute nodes sequentially following edges
- Pause at WAIT_FOR_DATE nodes
- Resume when external event occurs (date entered, etc.)
- Track execution state in execution_context

### Versioning Model
- Each payer can have multiple workflow versions
- Only one "is_active" at a time
- New provider assignments use active version
- Running instances continue with their version
- Set effective_from_date for future activation
